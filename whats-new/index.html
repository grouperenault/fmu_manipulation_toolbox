    What's new in 2.0¶

    Version 2.0 is the biggest release of FMU Manipulation Toolbox so far.

    Highlights¶

    • AI Assistant — an MCP server lets an AI agent (GitHub Copilot, Claude, local models…) inspect FMUs and build containers, in the Container Builder or standalone (fmutool-mcp).
    • Model-Exchange FMUs in containers — they are advanced by an embedded fixed-step solver, and can be mixed with Co-Simulation FMUs.
    • Several instances of the same FMU in one container, each with its own name.
    • Reset of embedded FMUs — an FMU of the container, or the importer, can reset another embedded FMU during the simulation: it starts again at the current time.
    • From Simulink to an FMU Container — the container initializes its FMUs as Simulink does: each one starts with the values of the FMUs it depends on. A migration guide maps the Simulink concepts to the container and lists the behaviour differences to take into account.
    • Link Assistant — connect FMUs with hundreds of ports by rule: same name, prefix or suffix, regular expression, similar names; review the proposals, then apply.
    • Compilation of the sources — no binary for your platform? FMU Tool compiles the C sources embedded in the FMU.
    • Safer edits, stricter checks — modelDescription.xml is edited in place, a semantic checker verifies the rules of FMI 2.0 and 3.0, and the exit codes suit continuous integration.
    • Python 3.10 to 3.14, and a command line that no longer needs the GUI toolkit.
    pip install "fmu-manipulation-toolbox[gui]"

    See the Installation Guide for the other extras.

    Breaking changes

    2.0 contains breaking changes, marked 🔴 BREAKING in the changelog: read them before updating your scripts, custom operations or checkers.

    The full list of changes is in the changelog.
