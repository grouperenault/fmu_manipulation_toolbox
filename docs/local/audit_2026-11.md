# Plan: follow-up of the November 2026 audit

**Created**: 22 November 2026 — **Status**: draft, decisions A1 to A17 open — **Branch**: to be decided (A2) —
**Roadmap**: "Audit"

## Context

An audit of the whole toolbox in November 2026 covered three areas: the performance of the container, the
maintainability of the code, and how well it follows the standards (FMI 2.0 / 3.0, SSP, layered standards). The raw
notes are in `docs/local/notes.md`, in French and partly corrupted. Most of the actions were already carried out
by `docs/local/done/perf_maintainability.md` (14-15 November 2026) and by the commits that followed. This plan
gathers **only what is still open**. Each item was checked again in the code on 22 November 2026 (file and line
given).

## 1. Open items

### C — Conformity of the generated container

| # | Item | Where | Notes |
|---|---|---|---|
| C1 | **Discrete real inputs of the ME FMUs are set in Continuous Time Mode.** `fmu_set_continuous_inputs()` picks the inputs by type (`reals64`, `reals32`), not by variability. FMI forbids this. Reproduced with `Feedthrough.fmu` (`Float64_discrete_input`): the step fails | `container/fmu.c:345`, `container/container.c:1126` | Found in `container_perf.md` §8. `perf_maintainability.md` announced a plan of its own for it |
| C2 | `variableNamingConvention="structured"` is hard-coded. An embedded FMU with `flat` names that are not valid `structured` names makes the container non-compliant | `container/builder.py:865` | |
| C3 | The `dependencies` of the outputs are not declared. The builder knows the graph of the links and could compute them | `container/builder.py` (`make_fmu_xml`) | |
| C4 | Log categories `Info` / `Error` instead of the categories recommended by the standard (`logEvents`, `logStatusWarning`, `logStatusError`...) | `container/builder.py:897` | |
| C5 | `license="Proprietary"` and `copyright` are hard-coded | `container/builder.py:863` | |
| C6 | `fmuCompletedIntegratorStep()` is called on every ME FMU at every sub-step. The builder reads neither `completedIntegratorStepNotNeeded` (FMI 2.0) nor `needsCompletedIntegratorStep` (FMI 3.0) | `container/solver.c:666` | |
| C7 | `canGetAndSetFMUstate` / `canSerializeFMUstate` are always `false`. They could be supported when every embedded FMU supports them (the cache, the local variables and the time would need to be serialized) | `container/builder.py:874` | Evolution, not a defect |
